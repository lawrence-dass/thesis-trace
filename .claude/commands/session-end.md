# Session End — Handover Instructions

Save the session state so any agent can resume seamlessly in a new window.
Write for a stranger reading cold — specificity is the point.

If the user passed arguments, treat them as the focus for the next session and tailor the handover accordingly.

---

## Step 1: Detect Mode

Run:
```bash
git branch --show-current
git status --short
git log -1 --format="%h %s"
```

Determine what you were working on. Try in order, stop at first match:
1. An active task/story file the session was editing (a checklist file, story file, or issue doc).
2. The current focus described by the user or evident from `git status`.
3. If unclear → ask: "What was this session focused on? Give a task name or path, or reply 'none' for a general handover."

**Set mode:**
- Work remains on the current task (unchecked items, incomplete feature) → **Mode 1: Mid-task**
- The task is finished and ready for review/merge → **Mode 2: Task complete**
- No specific task → **Mode: General handover**

---

## Step 2: Draft the Handover

Write `.claude/handoff/CURRENT.md`. Keep the body under 50 lines. Reference other files by path — do not copy their content.

```markdown
# Handover — {YYYY-MM-DD HH:MM} | {agent name + model}

## Mode
{Mid-task | Task complete | General handover}

## Focus
- **Task**: {task/story id or short name}
- **Branch**: {branch-name}
- **State**: {mid-task | complete-pending-review | blocked}
- **Progress**: {X of Y done, or a one-line status}

## Resume Point
{The exact next action, written for a stranger reading cold.
Name the subtask, the file, the approach, and why. Not "continue implementation".}

## Uncommitted Files
{list from git status, or "None — working tree clean"}

## What Happened This Session
- {bullet}
- {bullet}

## Decisions Made
{Decisions that would be re-debated or re-made without this note. Be specific.}

## Context Needed
{Anything the next agent must load or know that isn't obvious from the task file —
specific files, external constraints, WIP assumptions.}

## Next Action
{A concrete command or instruction — not "keep working".}

## References
- {task/status file paths that must be loaded next session}

---
*Generated by /session-end — {YYYY-MM-DD HH:MM}*
```

---

## Step 3: Validate Handoff Quality

Before showing the draft, verify each. Fix the draft if any fails:

| Check | Requirement |
|-------|-------------|
| Focus is specific | Names the exact task/subtask — not "working on the project" |
| Resume Point | Names a specific file, subtask, and approach — not "continue" |
| Next Action | A concrete command or instruction — not "keep working" |
| Reference files exist | Referenced paths actually exist in the repo |
| No duplication | References files by path — does not copy their content |
| No code snippets | File paths and function names are fine; full code blocks are not |
| Length | Body under 50 lines (headers/templates excluded) |

---

## Step 4: Show the Draft and Confirm

Present the draft in a single message and ask:

> "Approve writing this handover? Reply **yes**, **no**, or describe what to change."

- **yes** → proceed to Step 5.
- **no** → discard and exit.
- anything else → treat as edit instructions, revise, re-show, ask again.

---

## Step 5: Capture Cross-Session Learnings (Mode 2 only, optional)

If the task is complete, ask:

> "Any cross-project learnings to add to `.claude/context/project-context.md`? These load automatically in future sessions. (yes / no)"

If **yes**: ask what the learning is, draft a concise addition under a dated heading
`## Learnings — {YYYY-MM-DD}`, show it, and on approval add
`- project-context.md: .claude/context/project-context.md` to the **References** section of `CURRENT.md`.

---

## Step 6: Write Files

On confirmation:
1. **`.claude/handoff/CURRENT.md`** — write the approved content.
2. **Timestamped copy** — write identical content to `.claude/handoff/archive/{YYYY-MM-DD-HH-MM}.md`. Create the `archive/` directory if needed.
3. **Task/status file** — if Mode 2, mark the task complete / ready-for-review in whatever tracking file the project uses.
4. **`.claude/context/project-context.md`** — if learnings were approved, append the new section.

---

## Step 7: Confirm Complete

```
✅ Handover saved

  CURRENT.md         → .claude/handoff/CURRENT.md
  Timestamped copy   → .claude/handoff/archive/{timestamp}.md
  {if Mode 2} Task marked complete
  {if learnings} project-context.md → updated

Safe to close this window.
```

---

## Handoff Quality Rules

**Must include:** Focus/Mode · Active task · Decisions Made · Next Action · References.

**Keep lean:** reference files by path; point to task files, architecture docs, and status files rather than copying them.

**Avoid:** full code snippets (use `path:line`), verbose history, anything not needed for the next session.
