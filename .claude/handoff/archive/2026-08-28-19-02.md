## Decisions Made
- **Architecture**: Supabase (DB) + Render (backend) + Vercel (frontend),
  all free tiers — matches the stack already named in `CLAUDE.md`, just
  free instead of the ~$25/mo target.
- **No cron/live pipeline for the demo**: the 7-filer dataset was migrated
  once via `pg_dump --data-only` (local Docker Postgres) →
  `pg_restore` (Supabase), not re-ingested live. Row counts verified to
  match exactly (issuers 7, filings 95, canonical_facts 6673, score_runs
  1064, score_results 6133, market_prices 83, fx_rates 19,
  data_quality_issues 31, reverse_dcf_runs 7).
- **Supabase must use the Session pooler connection string**, not the
  direct connection — the direct string is IPv6-only and this network has
  no IPv6 route ("No route to host"). Pooler host looks like
  `aws-0-us-east-1.pooler.supabase.com:5432`.
- **`DATABASE_URL` on Render must use `postgresql+asyncpg://`**, not plain
  `postgresql://` — SQLAlchemy silently falls back to `psycopg2` (not
  installed, this project only uses asyncpg) if the driver isn't specified
  in the scheme. This caused the first Render deploy to 500 on every DB
  query; fixed by editing the env var.
- **Render needs `PYTHON_VERSION=3.12.13` set explicitly** — its default
  build image doesn't have Python 3.12+ and won't network-download one on
  the free tier (`uv sync` failed with "No interpreter found").
- **No CORS config needed** — confirmed all backend calls happen server-side
  in Next.js (SSR `fetch()` in Server Components), never from the browser,
  so the Vercel/Render cross-origin gap never actually matters.
- Read-only backend service only strictly needs `DATABASE_URL` —
  `EDGAR_CONTACT`/`TIINGO_API_KEY`/`LLM_API_KEY` are unused by the read API
  (only the live-ingestion pipeline needs them, which isn't deployed here).
